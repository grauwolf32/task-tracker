# Taskline

Локальный просмотрщик и редактор YAML-задач: список, доска, поиск, зависимости, создание и редактирование задач. Приложение работает на Python 3.10+, PyYAML и ruamel.yaml. Фронтенд — обычные HTML, CSS и JavaScript без сборки.

## Запуск

```sh
./start.sh --tasks /absolute/path/to/project/tasks
```

Открыть [http://127.0.0.1:4310](http://127.0.0.1:4310). При первом запуске создаётся `.venv` и устанавливаются зависимости из `requirements.txt`; для установки понадобится интернет. Сервер слушает только `127.0.0.1`.

В текущей локальной настройке без `--tasks` читается `~/src/contractor/tasks`. Для другого проекта передайте свою папку. Порт можно изменить через `--port 4311`.

## Просмотр и навигация

- Список и доска по статусам, по 40 задач на странице (на доске — на колонку).
- Поиск по ID и содержимому задачи; фильтры статуса, приоритета, типа, эпика и этапа.
- Сортировка по статусу, приоритету или названию направления; ↑/↓ меняет порядок. На доске сортируются карточки внутри колонок.
- Разделы открытых, текущих, готовых к работе и завершённых задач, весь архив.
- Карточка с целью, контекстом, границами, требованиями, критериями приёмки и командами проверок.
- Вкладка **Связи** показывает прямые зависимости, текущую задачу и зависимые задачи. Карточки связей открываются по нажатию. В каждой стороне схемы показаны первые 100 связей; остальные доступны в YAML или через поиск ID.
- Исходный YAML можно посмотреть и скопировать. Ссылка на карточку содержит `#TASK-ID`.
- Светлая и тёмная темы, адаптивная вёрстка. `/` — поиск, Esc — закрыть карточку.

**Эпик** — постоянная область проекта. Названия и описания читаются из `epics.yml` или `epics.yaml`; при выборе эпика показана сводка завершения. **Этап** (`milestone`) — отдельный срез поставки. Задачи готовы к работе только при `status: pending` и завершённых зависимостях: отсутствующие, отложенные и архивные задачи не считаются выполненными.

## Эпики

Раздел **Эпики** показывает направления из каталога, включая те, для которых ещё нет задач. На карточках видны описание, количество задач и прогресс. Поиск работает по ID, названию и описанию эпика; каталог разбит на страницы по 24 карточки. Направления, указанные в задачах, но отсутствующие в каталоге, отмечены отдельно.

Карточка эпика открывает его полное описание, пути спецификаций из поля `specs` и все связанные задачи, включая завершённые и архивные. Спецификации показаны как пути документов; просмотр файлов проекта через сервер не открывается. Поле `specs` необязательно и содержит до 100 непустых строк.

Прогресс — доля задач со статусом `completed` среди всех задач эпика. Архивные задачи не считаются завершёнными. Сводка относится ко всему эпику, даже когда список задач отфильтрован. В списке доступны обычные фильтры, сортировка, доска и постраничный просмотр. Закрытие задачи возвращает к выбранному эпику.

Каталог доступен по `#epics`, отдельный эпик — по `#epic/<ID>`. Изменения YAML автоматически обновляют описания и счётчики.

## Автообновление

Раз в две секунды приложение проверяет изменения файлов. Сервер сравнивает метаданные и отвечает `304`, если ничего не изменилось; неизменённые YAML повторно не разбираются. Учитываются создание, изменение, удаление, перенос в `done/` и изменения каталога эпиков.

Автообновление сохраняет фильтры, сортировку, доступную страницу, открытую вкладку карточки и её прокрутку. В скрытой вкладке опрос приостанавливается, при возвращении данные проверяются сразу. При сетевой ошибке остаётся последний успешный снимок, повторные запросы идут с задержкой 4–32 секунды. Тайм-аут запроса — 10 секунд. Кнопка ↻ запускает немедленную проверку.

## Создание задач

Кнопка **Новая задача** открывает форму с ID, названием, описанием, эпиком, приоритетом, типом и зависимостями. Название и описание обязательны. Сервер предлагает следующий ID по существующей нумерации проекта; его можно изменить. Предложение не резервирует ID: совпадение при сохранении возвращает конфликт, сохраняя черновик.

Зависимости выбираются через поиск по всему списку задач, включая завершённые. Выбранные задачи сохраняются при смене запроса; остальные результаты доступны через «Показать ещё». Максимум — 100 зависимостей. Проверяются отсутствующие и повторяющиеся ID, зависимость от самой себя и циклы.

Эпики берутся из `epics.yml`/`epics.yaml`. Если каталога нет, используются направления существующих задач. При пустом каталоге сначала добавьте в него направления. Неизвестный или удалённый эпик не может быть записан через форму.

В дополнительном разделе можно перечислить критерии готовности и команды, проверяющие все перечисленные критерии, по одному на строку. Они сохраняются как `acceptance_criteria` с ID `A1`, `A2` и далее, и `tests` со связями `covers`. Укажите оба списка вместе или оставьте оба пустыми. Каждый список ограничен 100 строками по 4000 символов; весь запрос создания или редактирования, включая JSON и кодировку UTF-8, — 256 КиБ. Без них создаётся базовая карточка; требования, этап поставки и другие обязательные поля конкретного проекта нужно дополнить по его правилам.

Новая задача сохраняется в статусе `pending` в файл `<id-в-нижнем-регистре>.yml` в корне папки задач. Существующие файлы не перезаписываются. Форма блокирует повторную отправку во время запроса; при неизвестном результате сохраняет тот же ID и черновик для проверки результата. Автоматически повторяются только чтения. Если повторное чтение подтвердило отсутствие задачи, можно явно повторить запрос с тем же ID и данными. Создание недоступно, пока исходные файлы содержат ошибки или список прочитан не полностью.

## Редактирование

Вкладка **Изменить** сохраняет `title`, `goal` и `status` в исходном YAML, сохраняя его комментарии. При завершении или архивировании файл переносится в `done/`, при возврате к открытому статусу — в корень папки задач.

Сохранение проверяет версию файла (`If-Match`). Если файл изменился после открытия формы, сервер возвращает конфликт, а черновик остаётся в интерфейсе. Не записывайте один и тот же файл одновременно из UI и внешнего редактора: проверка версии обнаруживает предшествующие изменения, но локальная файловая система не предоставляет общей транзакции с независимыми редакторами.

Редактор меняет файлы задач. Он не запускает тесты проекта, не подтверждает выполнение критериев приёмки, не генерирует `BACKLOG.md` и не создаёт коммиты. Завершение задачи нужно оформлять по правилам её проекта.

## Формат и пределы

Читаются `.yml` и `.yaml` непосредственно в папке задач и в `done/`; `templates/` не обходится. `index.yml`/`index.yaml` — политика проекта, `epics.yml`/`epics.yaml` — каталог направлений. Они не считаются задачами.

Минимальный пример:

```yaml
id: TASK-001
title: Add a project search
status: pending
priority: P2
kind: feature
epic: product
milestone: search-v1
goal: Find a task by its ID or title.
depends_on: []
```

Поддерживаются статусы `pending`, `in_progress`, `deferred`, `completed`, `archived`; приоритеты `P0`–`P3`; типы `feature`, `defect`, `chore`. Остальные поля сохраняются и отображаются в карточке. Ошибки файлов видны в интерфейсе и не скрывают корректные задачи. Все файлы с повторяющимся ID исключаются из списка и не могут быть выбраны для записи. Проверяются типы полей, повторяющиеся ключи и циклические ссылки YAML; вложенные скалярные ключи метаданных преобразуются в строки только без коллизий.

Лимиты: 10 000 файлов задач, 1 МиБ на файл, 48 МиБ исходных данных, 64 МиБ ответа. Развёрнутый YAML ограничен 50 000 значений, глубиной 50 и 4 МиБ текста на документ. Обычные файлы читаются с ограничением размера; символические ссылки и специальные файлы не поддерживаются. Неполный снимок из-за превышения лимитов не используется для выбора задач на запись.

## Навык для агентов

В репозитории находится переносимый навык [manage-project-tasks](.agents/skills/manage-project-tasks/SKILL.md). Он описывает ведение YAML-задач на любом проекте: от постановки и зависимостей до проверок и оформления завершения.

Навык содержит шаблоны feature/defect/chore, начальную политику и каталог эпиков, и опциональный скрипт `scripts/taskctl.py` с командами `validate`, `backlog`, `backlog --check`. Скрипт работает только при явном `tracker_format: file-tasks-v1` в политике проекта; он проверяет структуру и записанные доказательства, но не запускает указанные в задачах команды. Существующие правила проекта имеют приоритет; новый формат не применяется поверх существующего трекера автоматически.

Для использования в другом проекте скопируйте всю папку `.agents/skills/manage-project-tasks`. Агенту можно указать: «Используй навык manage-project-tasks из `.agents/skills/manage-project-tasks/SKILL.md` для постановки и ведения задач».

## Проверки

```sh
.venv/bin/python -m unittest -v
node --test test_ui.cjs
.venv/bin/python -m unittest discover -s .agents/skills/manage-project-tasks/scripts -v
```

Тесты проверяют настоящие чтения и записи временных файлов, конфликты версий, переносы, HTTP, состояния формы при ошибках и правила трекера. Для тестов JavaScript нужен Node.js; для работы самого приложения он не требуется.

Основные файлы: `server.py` — HTTP и загрузка задач; `storage.py` — запись YAML; `public/` — интерфейс; `test_server.py` — проверки на временных файлах и настоящем локальном HTTP-сервере. Проверки не изменяют рабочие задачи подключённого проекта.
